# Appendix C Model configurations

Table C.1 Configuration of the Track A models

| Model | Configuration |
|---|---|
| Mean baseline | Average daily demand of the training period |
| Seasonal naive | Demand of the same weekday seven days earlier |
| Prophet | Weekly seasonality, no yearly or daily seasonality, default changepoint settings. A2 adds the four covariates as regressors |
| LSTM | Input of the previous 28 days of standardised demand, one LSTM layer of 32 units, dropout 0.2, concatenated with the target day's calendar (and covariates in A2), dense layer of 16 units with ReLU, linear output. Adam optimiser with learning rate 0.001, batch size 16, at most 150 epochs, early stopping with patience 15 on the last 20 per cent of training windows |
| Random Forest | 300 trees, minimum of 2 samples per leaf. Inputs are demand lagged by 1, 2, 3, 7 and 14 days, the means of the previous 7 and 28 days, and the target day's calendar (and covariates in A2) |

Table C.2 Configuration of the Track B models

| Model | Configuration |
|---|---|
| Mean baseline | Average quantity of all training rows |
| Historical average rule | Average training quantity of the menu item |
| Linear regression | Ridge regression with alpha 1.0, one hot encoded categories and standardised numeric inputs |
| Neural network | Multilayer perceptron with hidden layers of 64 and 32 units, early stopping, at most 500 iterations, same encoding as the linear model |
| Random Forest | 300 trees, minimum of 2 samples per leaf, ordinal encoded categories |
| Gradient boosting | Histogram based gradient boosting with default settings, ordinal encoded categories |

All models use the random seed 42. Track B inputs for every model are the restaurant, restaurant type, menu item, meal type, weather, typical ingredient cost, observed market price, actual selling price, promotion flag, special event flag, weekend flag, day of the week, month, and the average and number of earlier sales of the same item at the same restaurant.

# Appendix D Running the application

The application is supplied as a folder. On Windows, double click START.bat. On the first run it creates a Python environment inside the folder and installs the required packages from the bundled backend\wheels folder, which takes about a minute and needs no internet connection when Python 3.9 to 3.13 is installed. Later runs start in a few seconds. The browser opens automatically, and the window reports the system checks and the address of the application. The demo account is manager@restaurant.com with the password password123.

If Python is not available, the folder portable\EcoServe contains EcoServe.exe, which runs without any installation. RESET_DATA.bat restores the original data after a demonstration, and RUN_TESTS.bat runs the automated tests. On macOS or Linux, start.sh performs the same steps as START.bat. Retraining the models requires the additional libraries listed in backend\requirements-ml.txt and is started with python precompute.py in the backend folder.
